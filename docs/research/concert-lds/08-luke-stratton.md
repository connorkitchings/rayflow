# Luke Stratton

**Era:** 2010s – present
**Role:** Lighting Director, various jam and electronic acts

## The Versatile Tour and Festival LD

Luke Stratton operates across the jam and electronic music spectrum, handling lighting for multiple acts on the touring and festival circuits. His work represents the practical, adaptable side of improvisational lighting — building effective shows under real-world constraints of time, budget, and rig variability.

## Programming Style

### Efficiency-First Busking
Stratton's layouts prioritize speed of deployment and ease of operation:
- **Streamlined fxecutor count:** 8–10 faders rather than 15–20. Each fader does more.
- **Multi-function faders:** HTP/LTP doubling on every executor maximizes control points from limited physical interface.
- **Clear, unambiguous labeling:** Every button and fader is labeled for intuitive operation. If a guest LD takes over, they can understand the layout in 30 seconds.

### Festival Adaptability
At festivals, Stratton may have 15 minutes of changeover between acts, no soundcheck lighting time, and a rig he's never seen before. His approach:
- Arrive with a USB stick containing a base show file (palettes, effects, busking layout)
- Merge the base file with the house patch
- Begin the show within 60 seconds of the band starting
- Refine throughout the first song as he learns the rig's quirks

### Cross-Act Consistency
Working with multiple acts, Stratton maintains a personal "base file" — a show file containing his preferred palettes, effects, and busking layout architecture. When starting with a new act, he begins from this base and customizes to the act's specific aesthetic, rather than building from scratch.

## RayFlow Relevance

1. **Base file generation:** RayFlow should generate a portable "base file" — universal palettes, standard busking layout, genre-appropriate effect templates — that an LD can load onto any console and customize.
2. **Multi-act management:** The show library should support multiple shows sharing a base palette and sequence infrastructure, with per-act overrides.
3. **Chronometry awareness:** The authoring system should estimate time-to-deploy for generated busking infrastructure. Can the LD load this show and be operational in 60 seconds? If not, the infrastructure is too complex.
4. **Guest LD documentation:** Generated busking layouts should include clear labeling and documentation sufficient for an unfamiliar operator to understand the layout quickly.
